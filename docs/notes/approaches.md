# アプローチのメモ

## 手法
1. ベースライン
2. 源流の入力画像を待機列のみが映るようにROI処理
3. 人物をオブジェクトではなく顔で検出
4. 人物を顔ではなく骨格(ポーズ)で検出
5. オブジェクト検出で人物を列挙(低い信頼度) → 切り取って(ROI処理して)、ポーズ検出で人物に絞る
  - 実用に耐えうる信頼度でフィルター
  - 後ろ姿対策と、後のアプローチの体の向き検出を兼ねてポーズ検出を採用
  - MediaPipe Pose Landmarkerを採用
  - 画像の切り出しは　固定サイズの非表示キャンバス + `createImageBitmap`でバウンディングボックスの範囲で指定で切り出し を実行
  - MediaPipe Pose Landmarkerの都合でワーカーは無理
  - `.close()`メソッドで明示的に開放ができるため、メインスレッドにも関わらずビットマップを採択した
  - 元画像のサイズから固定キャンバスのサイズを決める
  - 密集もあり得る上、ポーズ検出は優秀なので、切り取る時にマージンは不要
  - 源流で`Promise.all`でバウンディングボックス列挙で出た候補を同時にポーズモデルのマネージャーに投げる
  - 元のバウンディングボックスを生成したキャンバスから候補分をビットマップで切り出す
6. 待機列は等間隔で並ぶことが多い → 距離ではなく体の向き(スマホなどを操作している可能性も考慮して顔の向きは使わない)でグループ判定
  - おそらくこれでトイレで、連れに先に並んでもらっていた場合も解決する
7. 通行人の誤検出を避けるため前後の情報も組み合わせる
  - 直近のフレームのみ保存
  - 2フレーム以上映っていたら追跡開始
  - カルマンフィルター導入
  - 移動の検査の範囲はFPSや人物のバウンディングボックスのサイズから動的に求める
  - 前のフレームの周辺にある人物を色の検査にかけて、許容範囲内かも併用して判断する
  - 人物のポーズ検出で検出された体の部位ごとに、ポイントの周辺のピクセル(数ピクセルではなく`n x n`のような正方形などの領域)の色の平均を保持して、変化が許容範囲内か比較
  - 部位の色は一定の信頼度を超えたら新しい情報を使用
  - 色の探索の領域の大きさはバウンディングボックスのサイズから決まるため、FPSは関係ない
  - 影や照明の影響を抑えるため、色空間はRGBではなくHSVを使用し色味成分で比較
  - 彩度によって、色相と明度の重みの割合を変化させる
  - よって色相(H)は彩度(S)に連動して判断の厳しさを調整
  - また、無彩色などでは色相よりも明度の比重が高くなる
  - 数フレーム以上見失ったら人物削除

## 備考
- 連続稼働でOOMを防ぐため、全ての前後や現在の検出結果はスコープ外で変数を宣言して使い回し
- 各自開放処理忘れずに実装
- ラッパーが呼ばれるときに、FPS推定のため呼び出された時間(`performance.now()`)をグローバルで保持して、平均で何秒間隔で呼び出されるか(FPS)を求めて、移動を検出する範囲などで活用(初回フレームの精度は諦めるのでこれでいい)
- FPSは常時更新
